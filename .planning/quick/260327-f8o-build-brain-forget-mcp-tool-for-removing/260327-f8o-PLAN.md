1. Export a `ForgetResult` interface matching the existing Result pattern:
   ```typescript
   export interface ForgetResult {
     content: Array<{ type: 'text'; text: string }>;
   ```

2. Export a `forgetEntity` function with signature:
   ```typescript
   export function forgetEntity(
     db: Database.Database,
     params: { entity_name?: string; entity_type?: string; observation_id?: string; relationship_id?: string },
     stmts: MycoStatements,
   ): ForgetResult
   ```

   Logic — exactly ONE of these three modes based on which param is provided:

   **Mode 1: entity_name provided** (forget whole entity)
   - Default entity_type to 'concept' if not provided
   - Look up entity via `stmts.selectEntityByNameType.get(entity_name, entity_type)`
   - If not found, return `{ error: 'Entity not found', code: 'NOT_FOUND' }` in standard format
   - Get all observation IDs via `stmts.selectAllObservationIdsByEntityId.all(entityId)`
   - For each observation ID: run `stmts.deleteVecEmbeddingByItemId.run(obsId)` and `stmts.deleteFtsObservationByObsId.run(obsId)`
   - Count relationships via `stmts.selectRelationshipsByEntityIdBoth.all(entityId, entityId).length`
   - Delete entity via `stmts.deleteEntityById.run(entityId)` -- CASCADE handles observations and relationships rows
   - Call `invalidateEntityCache()` after deletion
   - Return JSON: `{ status: 'forgotten', type: 'entity', entity_name, observations_removed: N, relationships_removed: N }`

   **Mode 2: observation_id provided** (forget single observation)
   - Look up via `stmts.selectObservationById.get(observation_id)`
   - If not found, return NOT_FOUND error
   - Clean up: `stmts.deleteVecEmbeddingByItemId.run(observation_id)`, `stmts.deleteFtsObservationByObsId.run(observation_id)`
   - Delete: `stmts.deleteObservationById.run(observation_id)`
   - Return JSON: `{ status: 'forgotten', type: 'observation', observation_id }`

   **Mode 3: relationship_id provided** (forget single relationship)
   - Look up via `stmts.selectRelationshipById.get(relationship_id)`
   - If not found, return NOT_FOUND error
   - Delete: `stmts.deleteRelationshipById.run(relationship_id)`
   - Return JSON: `{ status: 'forgotten', type: 'relationship', relationship_id }`

   **Validation:** If none of entity_name, observation_id, relationship_id provided, return error: `{ error: 'Provide entity_name, observation_id, or relationship_id', code: 'INVALID_INPUT' }`

3. Register the `forget` tool in `registerTools()` following the exact pattern of existing tools:
   ```typescript
   server.registerTool(
     'forget',
     {
       description: 'Remove an entity, observation, or relationship from the knowledge graph. Deleting an entity cascade-deletes all its observations and relationships.',
       inputSchema: {
         entity_name: z.string().optional().describe('Name of the entity to forget (deletes entity + all observations + relationships)'),
         entity_type: z.string().default('concept').optional().describe('Entity type (used with entity_name to find exact entity)'),
         observation_id: z.string().optional().describe('ID of a specific observation to remove'),
         relationship_id: z.string().optional().describe('ID of a specific relationship to remove'),
       },
     },
     async ({ entity_name, entity_type, observation_id, relationship_id }) => {
       try {
         return forgetEntity(db, { entity_name, entity_type, observation_id, relationship_id }, stmts);
       } catch (err) {
         console.error('[forget] tool error:', err);
         return {
           content: [{ type: 'text' as const, text: JSON.stringify({ error: 'An unexpected error occurred', code: 'INTERNAL_ERROR' }) }],
         };
       }
     },
   );
   ```

Note: forgetEntity is synchronous (no async needed -- all DB operations are synchronous via better-sqlite3). The tool handler wraps it in async to match the registerTool pattern.
