    1. **Workflow rules** (highest priority):
       ```sql
       SELECT e.name, e.type, GROUP_CONCAT(o.content, '\n') as observations
       FROM entities e
       LEFT JOIN observations o ON o.entity_id = e.id AND o.valid_until IS NULL
       WHERE e.type = 'workflow_rule'
         AND (e.project = ? OR e.project IS NULL)
         AND e.merged_into IS NULL
       GROUP BY e.id
       ORDER BY e.confidence DESC
       ```
       Pass `projectName` (the resolved project_name, or use only `IS NULL` branch when no project).

    2. **Project facts** (medium priority):
       ```sql
       SELECT e.name, e.type, o.content, o.confidence
       FROM entities e
       JOIN observations o ON o.entity_id = e.id
       WHERE e.project = ?
         AND e.type != 'workflow_rule'
         AND e.type != 'user_preference'
         AND e.merged_into IS NULL
         AND o.valid_until IS NULL
       ORDER BY e.updated_at DESC, o.confidence DESC
       LIMIT 30
       ```
       Skip this query entirely when `projectName` is null.

    3. **User preferences** (lowest priority):
       ```sql
       SELECT e.name, GROUP_CONCAT(o.content, '\n') as observations
       FROM entities e
       LEFT JOIN observations o ON o.entity_id = e.id AND o.valid_until IS NULL
       WHERE e.type = 'user_preference'
         AND e.project IS NULL
         AND e.merged_into IS NULL
       GROUP BY e.id
       ORDER BY e.confidence DESC
       ```

    **Token budgeting (RECALL-02):**
    - Hard cap: 6,000 characters (~1,500 tokens at ~4 chars/token)
    - `buildInjection(rules, facts, preferences)` function:
      1. Format rules section: `## Workflow Rules\n` + each rule as `- **{name}**: {observations}`
      2. Format facts section: `## Project Knowledge\n` + each fact as `- [{entity_name}] {content}`
      3. Format preferences section: `## Preferences\n` + each pref as `- **{name}**: {observations}`
      4. Measure total length. If over 6,000 chars:
         - Keep rules section fully
         - Trim facts to fit remaining budget
         - Keep preferences section fully
         - Append `\n\nMore context available -- call \`myco recall\` for deeper search.`
      5. If under 6,000 chars but facts were limited by query LIMIT, still append the "More context available" note
    - Wrap in `<myco>` tags for output

    **Novelty filtering (RECALL-03):**
    - `computeContentHash(text)`: `crypto.createHash('sha256').update(text).digest('hex').slice(0, 16)`
    - Hash cache file: `path.join(dataHome, 'myco', 'last-injection-hash')` where dataHome = `$XDG_DATA_HOME || ~/.local/share`
    - On injection build: compute hash of assembled content
    - Read existing hash from cache file (if exists)
    - If hashes match: output short message "No changes since last session -- call `myco recall` if you need specific knowledge." instead of full injection
    - If different or missing: output full injection, then write new hash to cache file (this is the ONE write the hook does, to a file not the DB)
    - Include `projectName` and `cwd` in the hash input so different directories produce different hashes

    **Graceful degradation:**
    - No MCP server configured: `process.exit(0)` silently (existing behavior, keep it)
    - DB file doesn't exist: output "knowledge base is new" message (existing behavior, keep it)
    - DB exists but empty (no entities): output "knowledge base is new" message
    - No project match: inject global knowledge only + "No project context found for this directory -- run `myco link-project` to register it."
    - DB locked or query error: output brief fallback "Myco knowledge available -- call `myco recall` to access it." and exit 0
    - Timeout (>500ms): same fallback message

    - If exceeded at any point, close DB, output fallback, exit 0
