**Step 2: Create auth middleware at `packages/api-server/src/middleware/auth.ts`.**
Per research Pattern 3 and locked decision (Bearer token via `MYCO_API_KEY`, disabled when unset):
```typescript
import type { MiddlewareHandler } from 'hono';
import { timingSafeEqual } from 'node:crypto';

export function apiKeyAuth(): MiddlewareHandler {
  return async (c, next) => {
    const apiKey = process.env.MYCO_API_KEY;
    if (!apiKey) return next();  // Auth disabled when env var unset
    const header = c.req.header('Authorization');
    if (!header?.startsWith('Bearer ')) {
      return c.json({ error: { message: 'Unauthorized', code: 'UNAUTHORIZED', status: 401 } }, 401);
    }
    const provided = header.slice(7);
    try {
      const equal = timingSafeEqual(Buffer.from(provided), Buffer.from(apiKey));
      if (!equal) throw new Error();
    } catch {
      return c.json({ error: { message: 'Unauthorized', code: 'UNAUTHORIZED', status: 401 } }, 401);
    }
    return next();
  };
}
```

**Step 3: Create write routes at `packages/api-server/src/routes/memory.ts`.**
Use `OpenAPIHono` and `createRoute` from `@hono/zod-openapi`. Define 4 routes:

1. `POST /api/memory/remember` — body: `{ content, entity_name, entity_type?, confidence?, relations?, project? }` — calls `rememberEntity(db, body, stmts)`. Tag: `memory`.
2. `POST /api/memory/recall` — body: `{ query, limit?, entity_type?, min_confidence?, project?, as_of? }` — calls `recallKnowledge(db, body, stmts)`. Tag: `memory`.
3. `POST /api/memory/forget` — body: `{ entity_name?, entity_type?, observation_id?, relationship_id? }` — calls `forgetEntity(db, body, stmts)`. Tag: `memory`.
4. `POST /api/memory/query` — body: `{ entity_name?, entity_type?, relation_type?, project?, as_of?, history? }` — calls `queryEntities(db, body, stmts)`. Tag: `memory`.

Each route definition uses `createRoute()` with:
- Zod schemas with `.openapi({ example: ... })` annotations for good docs
- 200, 400, 401 response schemas
- Tag `'memory'`

The route handler extracts the result's `content[0].text` JSON string and parses it to return a proper JSON response (not the MCP envelope format). This means the HTTP response is `{ results: [...], metadata: {...} }` or `{ status: 'forgotten', ... }` directly — not wrapped in `{ content: [{ type: 'text', text: '...' }] }`.

Apply `apiKeyAuth()` middleware to all write routes:
```typescript
app.use('*', apiKeyAuth());
```

Export as a factory function following existing pattern:
```typescript
export function memoryRoutes(db: Database.Database, stmts: MycoStatements): OpenAPIHono {
  const app = new OpenAPIHono();
  app.use('*', apiKeyAuth());
  // ... define routes ...
  return app;
}
```

IMPORTANT per Pitfall 1: If using `app.route()` to mount the sub-app, OpenAPI spec may not include these routes. Two options:
- Option A: Register all routes directly on the main app (not a sub-app). This means memory.ts exports route definitions, not a Hono instance.
- Option B: Use `app.route()` and verify spec includes the routes.

Prefer Option A for reliability: define the write routes directly on the main `OpenAPIHono` instance in index.ts. The `memory.ts` file can export the route definitions and handler functions rather than a full Hono sub-app, OR the main app can be `OpenAPIHono` and the sub-apps mounted with `.route()` — test that `app.doc()` includes them.

Actually, the cleanest per research: register write routes on the SAME `OpenAPIHono` instance that calls `app.doc()`. So `memory.ts` exports a function that takes the app instance and registers routes on it:
```typescript
export function registerMemoryRoutes(app: OpenAPIHono, db: Database.Database, stmts: MycoStatements): void {
  app.openapi(rememberRoute, async (c) => { ... });
  // etc.
}
```
