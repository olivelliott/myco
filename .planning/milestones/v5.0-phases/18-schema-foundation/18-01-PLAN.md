1. Define the `Migration` interface:
```typescript
interface Migration {
  version: string;
  up: (db: Database.Database) => void;
}
```

2. Create a `columnExists` helper function:
```typescript
function columnExists(db: Database.Database, table: string, column: string): boolean {
  const info = db.pragma(`table_info(${table})`) as Array<{ name: string }>;
  return info.some(row => row.name === column);
}
```

3. Define the `MIGRATIONS` array with these exact migrations:

- `'001_baseline'`: All `CREATE TABLE IF NOT EXISTS` statements from current schema.ts lines 4-85 (entities, observations, relationships, episodes, approval_queue, vec_embeddings virtual table, fts_observations virtual table, all indexes). Copy the exact DDL from schema.ts.

- `'002_observations_needs_embedding'`: `ALTER TABLE observations ADD COLUMN needs_embedding INTEGER NOT NULL DEFAULT 0` + index `idx_observations_needs_embedding`. Guard with `columnExists(db, 'observations', 'needs_embedding')`.

- `'003_episodes_consolidated_at'`: `ALTER TABLE episodes ADD COLUMN consolidated_at TEXT` + index `idx_episodes_unconsolidated`. Guard with `columnExists(db, 'episodes', 'consolidated_at')`.

- `'004_approval_queue_metadata'`: `ALTER TABLE approval_queue ADD COLUMN metadata TEXT`. Guard with `columnExists(db, 'approval_queue', 'metadata')`.

- `'005_entities_project'`: `ALTER TABLE entities ADD COLUMN project TEXT DEFAULT NULL` + index `idx_entities_project`. Guard with `columnExists(db, 'entities', 'project')`.

- `'006_observations_temporal'`: `ALTER TABLE observations ADD COLUMN valid_from TEXT` and `ALTER TABLE observations ADD COLUMN valid_until TEXT`. Guard each with columnExists.

- `'007_observations_decay'`: Add `last_accessed_at TEXT`, `decay_exempt INTEGER NOT NULL DEFAULT 0`, `strength REAL NOT NULL DEFAULT 1.0`, `reinforcement_count INTEGER NOT NULL DEFAULT 0` to observations. Guard each with columnExists.

- `'008_entities_merged_into'`: `ALTER TABLE entities ADD COLUMN merged_into TEXT REFERENCES entities(id)`. Guard with columnExists.

- `'009_relationships_strength'`: Add `strength REAL NOT NULL DEFAULT 1.0` and `reinforcement_count INTEGER NOT NULL DEFAULT 0` to relationships. Guard each with columnExists.

4. Implement `runMigrations(db)`:
- First statement: `CREATE TABLE IF NOT EXISTS schema_migrations (version TEXT PRIMARY KEY, applied_at TEXT NOT NULL)`
- Prepare `checkApplied` and `recordMigration` statements outside the loop
- Loop over MIGRATIONS: skip if checkApplied returns a row, otherwise run `db.transaction(() => { migration.up(db); recordMigration.run(version, new Date().toISOString()); })()`
- Export `runMigrations` as the sole public export

The `columnExists` guard is essential for migrations 002-005 because existing v4.0 databases already have those columns but no `schema_migrations` table. Without the guard, the ALTER TABLE would throw "duplicate column name" inside the transaction.
