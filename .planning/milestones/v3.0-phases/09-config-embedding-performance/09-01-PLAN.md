  <action>
    1. Install dotenv in the core package:
       `npm install dotenv --workspace=packages/core`

    2. Create `packages/core/src/config.ts` with two exports:

       `loadConfig()` — Call once at process entry. Does:
       - Calls `dotenv.config()` (loads `.env` from `process.cwd()`)
       - Builds a config object from process.env with these keys:
         - `dbPath`: `process.env.MYCO_DB_PATH ?? process.env.BRAIN_DB_PATH ?? null` (null = use default)
         - `ollamaHost`: `process.env.OLLAMA_HOST ?? 'http://127.0.0.1:11434'`
         - `ollamaModel`: `process.env.OLLAMA_EMBED_MODEL ?? 'nomic-embed-text'`
         - `consolidationModel`: `process.env.BRAIN_CONSOLIDATION_MODEL ?? 'llama3.2'`
         - `apiPort`: `parseInt(process.env.MYCO_API_PORT ?? '3001', 10)`
         - `logLevel`: `process.env.MYCO_LOG_LEVEL ?? 'info'`
       - Logs each key=value pair to stderr: `console.error('[config] dbPath = /path/to/brain.db')`
         For each config key, log the resolved value. For dbPath when null, log "(default)".
       - Stores the config in a module-level variable.
       - Returns the config object.

       `getConfig()` — Returns the stored config object. Throws if `loadConfig()` was not called first.

       Config type interface:
       ```typescript
       export interface MycoConfig {
         dbPath: string | null;
         ollamaHost: string;
         ollamaModel: string;
         consolidationModel: string;
         apiPort: number;
         logLevel: string;
       }
       ```

    3. Export `loadConfig` and `getConfig` and `MycoConfig` from `packages/core/src/index.ts` barrel.

    4. Create `.env.example` at project root with contents:
       ```
       # Myco Configuration
       # Copy to .env and customize. Existing env vars take precedence over .env values.

       # Database path (default: ~/.local/share/myco/brain.db)
       # MYCO_DB_PATH=

       # Legacy DB path alias (MYCO_DB_PATH takes precedence)
       # BRAIN_DB_PATH=

       # Ollama server host (default: http://127.0.0.1:11434)
       # OLLAMA_HOST=http://127.0.0.1:11434

       # Ollama embedding model (default: nomic-embed-text)
       # OLLAMA_EMBED_MODEL=nomic-embed-text

       # Ollama consolidation LLM model (default: llama3.2)
       # BRAIN_CONSOLIDATION_MODEL=llama3.2

       # API server port (default: 3001)
       # MYCO_API_PORT=3001

       # Log level: info or debug (default: info)
       # MYCO_LOG_LEVEL=info
       ```

    IMPORTANT (P4 pitfall): Because `consolidator.ts` reads `BRAIN_CONSOLIDATION_MODEL` at module scope (top-level const), and `consolidator.ts` is imported by `scheduler.ts` which is imported by `index.ts`, the `loadConfig()` call with `dotenv.config()` MUST execute before those dynamic imports resolve. Since ES module imports are hoisted, use this pattern in `index.ts`:

    Actually, in Node.js ESM, static imports are all resolved before any module-level code runs. This means `loadConfig()` on line 3 of index.ts executes AFTER all imports resolve. To fix this, `packages/mcp-server/src/index.ts` needs to use a separate preload file OR make the consolidator read env lazily.

    The simplest fix: In `packages/mcp-server/src/consolidator.ts`, change line 17 from:
    ```typescript
    const CONSOLIDATION_MODEL = process.env.BRAIN_CONSOLIDATION_MODEL ?? 'llama3.2';
    ```
    to a lazy getter:
    ```typescript
    function getConsolidationModel(): string {
      return process.env.BRAIN_CONSOLIDATION_MODEL ?? 'llama3.2';
    }
    ```
    Then replace all uses of `CONSOLIDATION_MODEL` in that file with `getConsolidationModel()`. (Search for `CONSOLIDATION_MODEL` in consolidator.ts to find all usages.)
