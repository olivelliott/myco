  <action>
    Create `packages/mcp-server/src/dedup-resolver.ts` with:

    ```typescript
    import type Database from 'better-sqlite3';
    import type { MycoStatements, ClassificationResult } from '@myco/core';
    import { embedText } from './embed-client.js';

    // Thresholds for classification (cosine distance from sqlite-vec)
    // Distance < 0.08 = near-duplicate (similarity > 0.92) = NOOP
    // Distance 0.08..0.35 = related/conflicting = UPDATE (supersedes)
    // Distance >= 0.35 = different topic = ADD
    const NOOP_THRESHOLD = 0.08;
    const UPDATE_THRESHOLD = 0.35;

    export async function classifyObservation(
      db: Database.Database,
      stmts: MycoStatements,
      entityId: string,
      content: string,
    ): Promise<ClassificationResult> { ... }

    export function retireObservation(
      stmts: MycoStatements,
      observationId: string,
      retiredAt: string,  // ISO 8601 — caller provides, NOT generated here
    ): void { ... }
    ```

    Classification algorithm:
    1. Fetch current observations for entity via `stmts.selectObservationsByEntityForDedup.all(entityId)`
    2. If no current observations exist, return `{ classification: 'ADD', reason: 'No existing observations for entity' }`
    3. Embed the new content via `embedText(content)`
    4. If embedding is null (Ollama down), fall back:
       - Check exact string match against existing observation contents
       - If exact match found, return NOOP
       - Otherwise return ADD (safe default — better to add a potential duplicate than to lose data)
    5. If embedding available, use `knnSearchForContradiction` to find closest existing observation for same entity:
       ```typescript
       const vec = new Float32Array(embedding);
       const closest = stmts.knnSearchForContradiction.get(vec, entityId) as { distance: number } | undefined;
       ```
    6. Apply thresholds:
       - `distance < NOOP_THRESHOLD` -> NOOP with reason "Near-duplicate (distance: X)"
       - `distance < UPDATE_THRESHOLD` -> UPDATE, find the specific observation ID to supersede by running a targeted query, reason "Supersedes existing (distance: X)"
       - `distance >= UPDATE_THRESHOLD` -> ADD with reason "New fact (distance: X)"

    For the UPDATE case, to identify WHICH observation to retire, query the vec_embeddings table joined with observations to find the closest observation belonging to the same entity. Add a helper that runs this as a dynamic query (since knnSearchForContradiction only returns distance, not item_id):
    ```sql
    WITH knn AS (
      SELECT item_id, distance FROM vec_embeddings
      WHERE embedding MATCH ? AND k = 1 AND item_type = 'observation'
    )
    SELECT knn.item_id FROM knn
    JOIN observations o ON o.id = knn.item_id
    WHERE o.entity_id = ? AND o.valid_until IS NULL
    LIMIT 1
    ```
