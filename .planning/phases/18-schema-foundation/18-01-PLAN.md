Create `packages/core/src/migrations.ts` with the following structure:

1. **Migration interface:**
```typescript
interface Migration {
  id: number;        // Sequential integer (1, 2, 3...)
  name: string;      // Descriptive name (e.g., "add_needs_embedding_column")
  up: (db: Database.Database) => void;  // Forward migration
}
```

2. **schema_migrations table creation** (in runMigrations, before checking migrations):
```sql
CREATE TABLE IF NOT EXISTS schema_migrations (
  id          INTEGER PRIMARY KEY,
  name        TEXT NOT NULL,
  applied_at  TEXT NOT NULL
);
```

3. **Migration runner `runMigrations(db)`:**
   - Create schema_migrations table if not exists
   - Query `SELECT id FROM schema_migrations` to get already-applied IDs
   - For each migration in the ordered array, if its ID is NOT in the applied set:
     - Run `migration.up(db)` inside a transaction (use `db.transaction()`)
     - INSERT into schema_migrations: `(id, name, applied_at)` with current ISO timestamp
   - Log each applied migration to stderr: `[myco] Applied migration ${id}: ${name}`

4. **Absorb existing try/catch ALTER TABLE blocks from schema.ts into numbered migrations:**
   - Migration 1: `add_needs_embedding` — `ALTER TABLE observations ADD COLUMN needs_embedding INTEGER NOT NULL DEFAULT 0` + the partial index
   - Migration 2: `add_consolidated_at` — `ALTER TABLE episodes ADD COLUMN consolidated_at TEXT` + the partial index
   - Migration 3: `add_approval_metadata` — `ALTER TABLE approval_queue ADD COLUMN metadata TEXT`
   - Migration 4: `add_entity_project` — `ALTER TABLE entities ADD COLUMN project TEXT DEFAULT NULL` + the project index

   Each migration.up function runs `db.exec(...)` with the ALTER TABLE. Use try/catch ONLY within each migration's up() to handle "duplicate column name" errors from SQLite (this is necessary because existing databases may already have these columns from the old try/catch pattern — the migration framework didn't exist when they were first applied). After the try/catch ALTER, always run the CREATE INDEX IF NOT EXISTS unconditionally.

5. **Clean schema.ts:** Remove ALL five try/catch blocks (lines 87-134). The `applySchema()` function should only contain the CREATE TABLE IF NOT EXISTS and CREATE INDEX IF NOT EXISTS statements that were already there (lines 4-85). Do NOT change the base table definitions.

6. **Update db.ts:** After `applySchema(db)` call on line 31, add `runMigrations(db)` call. Import runMigrations from './migrations.js'.

7. **Update index.ts:** Export `runMigrations` from './migrations.js'.

IMPORTANT: The migration up() functions must use try/catch on ALTER TABLE ADD COLUMN because SQLite throws "duplicate column name" if the column already exists — and existing databases already have these columns from the old code path. The schema_migrations INSERT happens AFTER success, so next startup will skip them.
