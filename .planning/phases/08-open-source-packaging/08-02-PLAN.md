**CONTRIBUTING.md:**

Create with the following exact section structure:

1. **Title** — `# Contributing to Myco`

2. **Introduction** — Brief welcome. Link to CODE_OF_CONDUCT.md. "By participating, you agree to abide by our [Code of Conduct](CODE_OF_CONDUCT.md)."

3. **Development Setup** — Step by step:
   - Prerequisites: Node.js 22.x, Ollama running locally with `nomic-embed-text` and `llama3.2` models pulled
   - Clone the repo: `git clone https://github.com/olive/myco.git && cd myco`
   - Install dependencies: `npm install --legacy-peer-deps` (explain why: Vite 8 peer dep conflict with some packages)
   - Build all packages: `npm run build`
   - Run tests: `npm test`
   - Dev mode: `npm run dev` runs the MCP server with tsx

4. **Project Structure** — Brief monorepo overview showing the 4 packages (core, mcp-server, api-server, dashboard) with one-line descriptions.

5. **Running Tests** — `npm test` runs Vitest across all packages. `npm run test:watch` for watch mode.

6. **Submitting a Pull Request** — Steps:
   - Fork the repo and create a branch from `main`
   - Make your changes
   - Run `npm run build` and `npm test` to verify nothing is broken
   - Write a clear PR description explaining what and why
   - Reference any related issues

7. **Reporting Bugs** — Point to the GitHub issue template. Include what to provide: steps to reproduce, expected vs actual behavior, Node.js/Ollama versions.

8. **Requesting Features** — Point to the feature request template. Describe the problem, not just the solution.

9. **Code Style** — TypeScript strict mode. ESLint configured. No specific formatter enforced yet — just match existing code style.

10. **License** — "By contributing, you agree that your contributions will be licensed under the Apache 2.0 License."

Keep it concise — aim for 80-120 lines total. Developer tool contributors do not need hand-holding.

**`.github/ISSUE_TEMPLATE/feature_request.md`:**

Must have YAML frontmatter with: `name: Feature Request`, `about: Suggest an idea for Myco`, `title: "[Feature] "`, `labels: enhancement`, `assignees: ""`.

- **Problem** — What problem does this solve? "I'm frustrated when..."
- **Proposed solution** — How you'd like it to work.
- **Alternatives considered** — Other approaches you thought about.
- **Additional context** — Any other context.
