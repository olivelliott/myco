## Spacing Scale

Declared values (all multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, badge internal padding, inline icon-text gap |
| sm | 8px | Compact element spacing, button icon padding, card internal row gap |
| md | 16px | Default element spacing, card padding, form field gap |
| lg | 24px | Section padding, sidebar item group gap, stat card spacing |
| xl | 32px | Layout column gap, graph panel width padding |
| 2xl | 48px | Major section breaks, dashboard grid row gap on desktop |
| 3xl | 64px | Page-level top/bottom padding on desktop |

Exceptions:
- Touch targets on mobile: minimum 44px height for approve/reject buttons (WCAG 2.5.5). This applies to action buttons on approval cards at mobile widths.
- Graph canvas: fills remaining viewport area after sidebar/bottom-nav — no fixed spacing token applies.
- Bottom tab nav on mobile: 56px height (standard mobile tab bar convention).

## Typography

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Body | 14px | 400 (regular) | 1.5 | Observation text, activity feed entries, entity panel content |
| Label | 12px | 500 (medium) | 1.4 | Badge text, stat card labels, form field labels, nav item labels |
| Heading | 18px | 600 (semibold) | 1.2 | Card titles, section headings, entity panel entity name |
| Display | 28px | 700 (bold) | 1.1 | Stat card numbers (pending count, entity count, episode count) |

Font stack: `ui-sans-serif, system-ui, -apple-system, BlinkMacSystemFont, sans-serif`

Rules:
- Exactly 4 sizes above — do not introduce a 5th size without updating this contract.
- Exactly 3 weights (400/500/600 — bold 700 reserved for display numbers only).
- Body and Label share 400/500 weight; headings use 600 only.
- No italic in the dashboard — italic is reserved for quoted evidence text in approval cards only (use `font-style: italic` on the evidence quote `<blockquote>` element).

```
│  [icon] Approvals  (N)  │                      │
│  [icon] Knowledge Graph │                      │
│  ─────────────────────  │                      │
│  (bottom) Version label │                      │
└──────────────────────────────────────────────┘
```

- Sidebar width: 240px at `md:` breakpoint and up.
- Sidebar background: slate-900 (`#1e293b`). Border-right: 1px slate-800.
- Active nav item: indigo-500 left border 2px + slate-800 background.
- Pending approval count shown as amber-500 badge inline on "Approvals" nav item.

### Root Layout (mobile, < 768px)

```
┌──────────────────────────┐
│      Main content        │
│      (full width,        │
│       pb-[56px])         │
├──────────────────────────┤
│  [home] [check] [graph]  │  ← 56px bottom tab bar, slate-900 bg
└──────────────────────────┘
```

- Sidebar collapses to bottom tab bar at `< md` (< 768px). Source: CONTEXT.md.
- Bottom tab icons: Lucide `LayoutDashboard`, `CheckSquare`, `Network`.
- Tab bar height: 56px. Tab touch target: full tab width × 56px.

### Dashboard View

Three stat cards in a responsive grid (`grid-cols-1 sm:grid-cols-3`) + activity feed + quick-approve list.

Stat card layout:
```
┌───────────────────────┐
│  Label (12px/500)     │
│  Number (28px/700)    │  ← amber-500 for pending count, slate-100 for others
│  Subtext (12px/400)   │
└───────────────────────┘
```

Activity feed: chronological, grouped by date (date-fns `format(date, 'MMM d, yyyy')`), relative timestamps via `formatDistanceToNow`. Source: CONTEXT.md.

Quick-approve list: top 5 pending items. Each row: entity name + observation preview (1 line truncated) + approve/reject icon buttons. No expand — full detail is in Approvals view.

### Approval Queue View

Card list, most recent first. Each card:

```
┌─────────────────────────────────────────────────────────┐
│  Entity Name (18px/600)          [reason badge] [conf.] │
│  Observation preview (14px/400, 2-line clamp)           │
│  [▼ Show evidence quote]  ← toggleable, italic 14px     │
│  ──────────────────────────────────────────────────     │
│  [Approve]  [Reject]  [Edit]                            │
└─────────────────────────────────────────────────────────┘
```

- Card background: slate-800 (`#1e293b`). Border: 1px slate-700. Border-radius: 8px.
- Reason badge colors: contradiction→red-500, low_confidence→amber-500, merge_candidate→indigo-500, cross_session→cyan-500.
- Confidence badge: slate-700 bg, value as percentage ("87%"), slate-200 text.
- Approve button: emerald-500 bg, white text, 36px height (44px on mobile).
- Reject button: red-500 bg, white text, 36px height (44px on mobile).
- Edit button: slate-700 bg, slate-200 text. Opens inline Textarea replacing observation preview. Then shows "Save & Approve" button (emerald-500).
- Card animates out on action: `transition-opacity duration-300` + `transition-transform`. Source: CONTEXT.md.

Entity merge candidate card:

```
┌──────────────────┬──────────────────┐
│  Entity A        │  Entity B        │
│  observations…   │  observations…   │
├──────────────────┴──────────────────┤
│  [Merge]   [Keep Separate]          │
└─────────────────────────────────────┘
```

Side-by-side layout, slate-800 bg per side, slate-700 divider. Source: CONTEXT.md.

## Interaction Contracts

### Approval Action Flow

1. User clicks Approve / Reject / Merge / Keep Separate.
2. Optimistic update: card immediately removed from list (`onMutate` with `cancelQueries`). Source: RESEARCH.md Pattern 3.
3. PATCH `/api/approvals/:id` fires.
4. sonner toast shown on success.
5. `onSettled`: `invalidateQueries(['approvals'])` + `invalidateQueries(['dashboard'])` — pending count badge updates.
6. On error: snapshot restored, error toast shown ("Action failed — changes rolled back").

### Edit Flow

1. User clicks "Edit" on an approval card.
2. Observation preview replaced in-place by a `<Textarea>` pre-filled with current observation content.
3. "Save & Approve" button appears (replaces Approve/Reject/Edit buttons).
4. On "Save & Approve": PATCH with `{ status: 'approved', edited_content: value }`. Same optimistic update flow.
5. On Escape key or blur without saving: textarea collapses, original buttons restored, no API call.

### Graph Node Interaction

1. User hovers node → Tooltip shows: `{entity name} ({type}) — {N} observations`. Tooltip uses shadcn Tooltip, 200ms delay.
2. User clicks node → Entity side panel slides in from right (`transition: transform 300ms ease`). TanStack Query fetches `/api/entities/:id` lazily (`enabled: !!selectedNodeId`).
3. User clicks outside panel or presses Escape → panel slides out.
4. While panel is loading: skeleton placeholder (3 lines slate-800 animated pulse).

### Search + Filter Flow (Graph)

1. User types in search input → client-side filter: nodes whose `name` contains the query (case-insensitive) remain full opacity; non-matching nodes go to 20% opacity.
2. User selects type filter → only nodes of that type shown; others hidden (removed from graphData passed to ForceGraph2D). Graph re-renders without re-mounting.
3. Clearing both inputs restores full graph.

### Responsive Breakpoints

| Breakpoint | Change |
|------------|--------|
| < 768px (`md`) | Sidebar → bottom tabs. Approval cards go full-width. Graph search + filter stack vertically. Entity panel covers full screen (not side panel). |
| 768px–1024px | Sidebar visible (240px). Dashboard grid 3-col. |
| > 1024px | Same as 768px–1024px. Graph entity panel stays at 320px side panel, not full-screen. |
