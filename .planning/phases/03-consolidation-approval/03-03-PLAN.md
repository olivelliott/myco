  <action>
Create `packages/mcp-server/src/cli.ts` with a `#!/usr/bin/env node` shebang. Use Node.js built-in `process.argv` for argument parsing (no external CLI framework needed for 3 subcommands).

The CLI must:

1. **Subcommand dispatch** — Read `process.argv[2]` as the subcommand. Valid subcommands: `consolidate`, `list-approvals`, `resolve-approval`. Print usage on unknown/missing subcommand.

2. **`consolidate` subcommand** — Call `openDatabase()` from `@ai-workbots/core`, then `runConsolidation(db)` from `./consolidator.js`. Print the ConsolidationSummary as formatted text to stdout:
   ```
   Consolidation complete.
   Episodes processed: {totalProcessed}
   Facts extracted:    {totalExtracted}
   Auto-approved:      {totalAutoApproved}
   Queued for review:  {totalQueued}
   ```
   Exit 0 on success, exit 1 on error (catch and print error.message).

3. **`list-approvals` subcommand** — Open DB, query `SELECT id, item_type, reason, metadata, created_at FROM approval_queue WHERE status = 'pending' ORDER BY created_at`. Accept optional `--limit N` flag (default 20). Print each item as a formatted block:
   ```
   [{id}] {reason} ({created_at})
     Type: {item_type}
     Entity: {fact.entity_name} ({fact.entity_type})
     Observation: {fact.observation}
     Confidence: {fact.confidence}
     Evidence: "{fact.evidence_quote}"
   ```
   Where fact fields come from JSON.parse(metadata).fact. Print "No pending approvals." if empty.

4. **`resolve-approval` subcommand** — Read `process.argv[3]` as the approval ID, `process.argv[4]` as the action (`approve`, `reject`, `edit`). For `edit` action, read `--content "..."` from remaining args. Replicate the exact same logic as the `resolve_approval` MCP tool in tools.ts lines 547-649:
   - Fetch item from approval_queue by ID
   - Validate status is 'pending'
   - For 'reject': UPDATE status = 'rejected', resolved_at = now
   - For 'approve'/'edit': Parse metadata JSON, get observation (use edited_content for edit), handle merge_candidate entity reassignment, call `rememberEntity()`, UPDATE status = 'approved'
   - Print result as formatted text, not JSON
   - Exit 0 on success, exit 1 on error

5. **Usage message** — When no subcommand or `--help`:
   ```
   Usage: brain-cli <command>

   Commands:
     consolidate              Trigger consolidation pipeline
     list-approvals [--limit N]  Show pending approval queue
     resolve-approval <id> <approve|reject|edit> [--content "..."]  Resolve a queued item
   ```

All logging uses `console.error()` for diagnostic output (consistent with existing pattern). Only structured output goes to `console.log()` / stdout.

Update `packages/mcp-server/package.json`:
- Add `"brain-cli": "./dist/cli.js"` to the `bin` object (alongside existing `"brain-mcp": "./dist/index.js"`)

Use `.js` extensions in all relative imports (NodeNext module resolution per project convention).
