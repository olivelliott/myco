**TimelineSlider rewrite** (packages/dashboard/src/components/timeline-slider.tsx):

1. Change props interface to:
```typescript
interface TimelineSliderProps {
  minMs: number              // earliest entity timestamp (ms)
  maxMs: number              // latest entity timestamp (ms)
  cutoffRef: React.MutableRefObject<number>  // shared ref: the current cutoff timestamp in ms
  onScrub: (ms: number) => void  // called ONLY on manual slider scrub (syncs React state for display)
  onPlayStateChange?: (playing: boolean) => void  // optional callback when play/pause toggles
}
```

2. Internal state: `playing` (boolean), `speed` (1/2/5), `displayMs` (number — for slider position display only).

3. **rAF playback loop** — when `playing` is true:
   - Use `useRef` for the rAF ID and previous timestamp
   - In the rAF callback: compute `elapsed = (now - prevTimestamp) * speed`, advance `cutoffRef.current += elapsed * daysPerMs` where `daysPerMs` converts real-time ms to timeline ms (1 real second = 1 day of timeline by default, so `daysPerMs = 86_400_000 / 1000`)
   - Clamp `cutoffRef.current` to `[minMs, maxMs]`
   - Update `displayMs` via setState only every ~250ms (use a `lastDisplayUpdateRef` to throttle) for the date label — NOT every frame
   - When cutoffRef.current >= maxMs: stop playing, call `onScrub(maxMs)` to sync final state
   - Do NOT call `onScrub` during auto-play — the ref IS the source of truth for the canvas painter

4. **Manual scrub** — on slider `onChange`:
   - If currently playing, pause first
   - Set `cutoffRef.current` to the scrubbed value
   - Set `displayMs` for label
   - Call `onScrub(newMs)` so graph.tsx can update React state if needed

5. **Play/Pause button**: toggles `playing`. On play start, set `cutoffRef.current` to current `displayMs` if it equals maxMs (restart from beginning).

6. Keep the existing visual design (absolute positioned bar, bioluminescent theme, speed selector).

7. Add a `useEffect` cleanup that cancels the rAF on unmount.

8. Trigger a canvas repaint during playback: call `fgRef.current?.refresh()` is NOT available here. Instead, the `onRenderFramePost` in GraphView will naturally repaint at 60fps because ForceGraph2D runs its own rAF loop. The cutoff ref is read directly by the canvas painters — no external refresh needed.

**Add timelineCutoffRef prop to GraphViewProps**:
```typescript
timelineCutoffRef?: React.MutableRefObject<number>  // ms timestamp; Infinity = show all
```

**nodeCanvasObject changes** — at the top of the painter, before any drawing:

1. Read `const cutoffMs = timelineCutoffRef?.current ?? Infinity`
2. Parse node's created_at: `const nodeMs = n.created_at ? new Date(n.created_at).getTime() : 0`
3. If `nodeMs > cutoffMs`: skip drawing entirely (`return`). The node is "in the future" — invisible.
4. **Entry pulse detection**: if the node just appeared (nodeMs is within a "recently appeared" window), draw an expanding ring.
   - Store a `Map<string, number>` in a `useRef` called `entryTimesRef` — maps node ID to the real-time timestamp (Date.now()) when that node first became visible during this playback session.
   - In the painter: if `nodeMs <= cutoffMs` and `!entryTimesRef.current.has(n.id)`, record `entryTimesRef.current.set(n.id, Date.now())`.
   - If entry time exists and `Date.now() - entryTime < 800` (800ms pulse duration):
     - Compute `progress = (Date.now() - entryTime) / 800` (0 to 1)
     - Draw an expanding ring: radius = `baseSize * (1 + progress * 2)`, opacity = `0.6 * (1 - progress)`
     - Ring color = node's type color
   - After 800ms, the entry in `entryTimesRef` can be left (harmless) — the condition simply stops triggering.
   - **Reset entryTimesRef** when `timelineCutoffRef` jumps backward (user scrubs left) or when timeline is disabled. Add a `prevCutoffRef` that tracks the previous cutoff value. If `cutoffMs < prevCutoffRef.current`, clear `entryTimesRef.current`.

5. Apply the existing confidence/search opacity logic AFTER the timeline check — a node below confidence threshold that is within the timeline should be faded, not hidden.

**linkCanvasObject changes**:

1. At the top of the link painter, read cutoff from ref.
2. Parse link's created_at: `const linkMs = l.created_at ? new Date(l.created_at).getTime() : 0`
3. Also check both source and target node created_at — a link should only be visible if BOTH its endpoints are visible (nodeMs <= cutoffMs).
4. If link is invisible: `return` (skip drawing).

**onRenderFramePost changes**:

1. The cluster hull drawing in `onRenderFramePost` should also respect the cutoff — only include nodes whose `created_at <= cutoffMs` in hull computation. Read the ref inside the callback.

**Force a canvas repaint during playback**:

The ForceGraph2D library runs its own internal rAF loop for the canvas, but after `cooldownTicks(0)` freezes the simulation, it may stop repainting. To ensure continuous repaints during timeline playback:
- Add a `useEffect` that, when `timelineCutoffRef` is provided (timeline mode active), starts a lightweight rAF loop calling `fgRef.current?.refresh()` at 60fps. Return cleanup cancelling the rAF.
- Guard: only run this rAF loop when timeline is active. Use a new prop `timelineActive?: boolean` passed from graph.tsx (true when timelineEnabled is true).

**Performance considerations**:
- `new Date(n.created_at).getTime()` is called per-node per-frame. Pre-compute and store `_createdAtMs` on the node during `decoratedNodes` memo to avoid repeated parsing. Add `created_at_ms: number` to the decorated node and compute once in the memo.
- The `entryTimesRef` Map will accumulate entries during playback. This is fine — a knowledge graph with < 10k nodes means < 10k Map entries, negligible memory.

**CRITICAL — Do NOT:**
- Filter nodes out of graphData (stableGraphData must remain stable)
- Store entry pulse state in useState (Pitfall 4)
- Modify the stableGraphData memoization (it must only change on structural ID set changes)
