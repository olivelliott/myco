  <action>
Create `.claude/hooks/gsd-brain-episode.js` as a CommonJS script (no build step needed). Follow the exact patterns from the research document.

**Structure:**
1. Stdin reader with 10s timeout guard (same pattern as gsd-context-monitor.js)
2. Command detection: `/gsd-tools[^\s]*\s+phase\s+complete/` regex on `data.tool_input.command`
3. Phase number extraction: `/phase\s+complete\s+["']?([^\s"']+)["']?/i` regex
4. brain.db path resolution: check `BRAIN_DB_PATH` env, then `XDG_DATA_HOME`, then `~/.local/share/ai-workbots/brain.db` -- identical to `packages/core/src/db.ts` `getDefaultDbPath()`
5. Existence check: `fs.existsSync(dbPath)` -- if false, exit 0 (do NOT let better-sqlite3 auto-create an empty DB)
6. Require better-sqlite3 via absolute path: `require(path.join(projectRoot, 'node_modules', 'better-sqlite3'))` where projectRoot is derived from `__dirname` (hook lives in `.claude/hooks/`, project root is 2 levels up)
7. Open DB (no sqlite-vec needed, no schema apply needed)
8. Build payload object per GSD-02:
   - `phase_name`: extracted from ROADMAP.md phase section title (e.g., "gsd-integration") or derived from phase number
   - `phase_number`: from command string
   - `requirements_covered`: parsed from ROADMAP.md `**Requirements:**` line for the matched phase
   - `outcome_summary`: read `*-SUMMARY.md` files from `.planning/phases/{phase-dir}/` and concatenate summaries; fallback to `"Phase {N} complete"` if unreadable
   - `plans_executed`: count of `*-SUMMARY.md` files found (as a proxy for plans executed)
   - `source`: `"gsd_hook"`
   - `transition_timestamp`: `new Date().toISOString()`
9. Generate episode ID with `crypto.randomUUID()` (Node.js built-in -- avoids nanoid ESM/CJS issues per research open question 3)
10. INSERT into episodes table: `(id, session_id, agent_id, event_type, payload, created_at)` with values `(uuid, data.session_id, 'gsd-hook', 'gsd_phase_complete', JSON.stringify(payload), new Date().toISOString())`
11. Close DB, exit 0

**Critical failure isolation:** Wrap the entire logic in try/catch that exits 0. Each sub-operation (DB open, file reads, INSERT) has its own try/catch. Use `console.error()` for any diagnostic logging (never `console.log()` which writes to stdout).

**Phase directory discovery:** The phase number from the command (e.g., "5" or "05") needs to find the correct `.planning/phases/XX-name/` directory. Use `fs.readdirSync(path.join(cwd, '.planning', 'phases'))` and find the directory starting with the zero-padded phase number.
