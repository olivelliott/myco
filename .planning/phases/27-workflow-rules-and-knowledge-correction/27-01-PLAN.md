    2. Implementation — this is a thin wrapper over `rememberEntity()`:
       - Import `createHash` from `node:crypto` at the top of the file
       - Generate entity name: `rule:${createHash('sha256').update(instruction).digest('hex').slice(0, 8)}`
       - Call `rememberEntity(db, { content: instruction, entity_name, entity_type: 'workflow_rule', confidence: 1.0, source_type: 'agent_session', agent_id, project }, stmts)`
       - If triggers is provided and non-empty, store it as part of the observation content by appending: `\n[triggers: ${triggers.join(', ')}]`
       - Per CONTEXT.md decision: entity_type='workflow_rule', decay_exempt=true, confidence=1.0

    3. For decay_exempt: After the `rememberEntity` call, run a direct SQL update on the entity:
       `db.prepare('UPDATE entities SET decay_exempt = 1 WHERE name = ? AND type = ?').run(entity_name, 'workflow_rule')`
       This is needed because `rememberEntity` does not accept a `decay_exempt` parameter.

    4. Register the MCP tool inside `registerTools()`, before the closing `}`:
       ```typescript
       server.registerTool(
         'remember_rule',
         {
           description: 'Store a workflow rule — an actionable instruction that will be surfaced at the start of every session. Rules are never similarity-ranked out.',
           inputSchema: {
             instruction: z.string().describe('The rule or instruction to remember (e.g. "always run tests before pushing")'),
             project: z.string().optional().describe('Project to scope this rule to (omit for global rule)'),
             triggers: z.array(z.string()).optional().describe('Optional trigger contexts when this rule applies (e.g. ["git commit", "git push"])'),
           },
         },
         async ({ instruction, project, triggers }) => {
           try {
             return await rememberRule(db, { instruction, project, triggers }, stmts);
           } catch (err) {
             console.error('[remember_rule] tool error:', err);
             return {
               content: [{ type: 'text' as const, text: JSON.stringify({ error: 'An unexpected error occurred', code: 'INTERNAL_ERROR' }) }],
             };
           }
         },
       );
       ```

       ```typescript
       export async function updateKnowledge(
         db: Database.Database,
         params: { query: string; new_value: string; entity_name?: string; confirm_id?: string },
         stmts: MycoStatements,
       ): Promise<{ content: Array<{ type: 'text'; text: string }> }>
       ```

    2. Two-phase operation controlled by `confirm_id`:

       **Phase 1 — Search (confirm_id is undefined):**
       - Search for matching active observations using the same dual-path pattern as `recallKnowledge`:
         a. Try embedding search first via `embedText(query)` — if embedding available, use dynamic SQL joining vec_embeddings KNN with observations+entities, filtered by `valid_until IS NULL`
         b. If embedding unavailable, use FTS5 fallback via dynamic SQL: `fts_observations MATCH ? JOIN observations WHERE valid_until IS NULL`
         c. If `entity_name` provided, add `AND e.name = ?` filter
       - Return top 3 candidates as JSON:
         ```json
         {
           "action": "confirm",
           "candidates": [
             { "id": "<observation_id>", "entity_name": "...", "content": "...", "confidence": 0.9, "created_at": "..." }
           ],
           "instructions": "Call update_knowledge again with confirm_id set to the observation ID you want to replace, and new_value set to the replacement text."
         }
         ```

       **Phase 2 — Confirm + Replace (confirm_id is provided):**
       - Look up the observation by ID: `stmts.selectObservationById.get(confirm_id)`
       - If not found, return error: `{ error: "Observation not found", code: "NOT_FOUND" }`
       - Get the entity_id from the observation row
       - Execute in a single transaction (`db.transaction()`):
         a. Retire old observation: `retireObservation(stmts, confirm_id, now)`
         b. Insert new observation: `stmts.insertObservationTemporal.run(newObsId, entityId, new_value, SESSION_ID, null, 'agent_session', 1.0, now, now)`
         c. Insert FTS entry: `stmts.insertFtsObservation.run(new_value, newObsId)`
         d. Try embedding: `const embedding = await embedText(new_value)` — if available, insert vec_embedding; if not, flag needs_embedding
       - Note: `embedText` is async so it cannot be inside `db.transaction()`. Structure as:
         a. Run the transaction (retire + insert obs + insert FTS)
         b. After transaction commits, attempt embedding and insert/flag
       - Return success: `{ action: "updated", retired_id: confirm_id, new_observation_id: newObsId, entity_name: "...", new_content: new_value }`
